17enum class SysExMessageType
18{
19 Unknown = 0,
20 ProgramDump, // 0x40: 1 Program Data Dump
21 AllDataDump, // 0x4C: All Data Dump (128 Programs)
22 ParameterChange, // 0x41: 1-Parameter Change
23 ProgramDumpRequest, // 0x10
24 AllDataDumpRequest, // 0x0E
25 WriteCompleted, // 0x23: el otro extremo guardó lo que le mandamos (ACK)
26 WriteError // 0x24: el otro extremo no pudo guardarlo (NACK)
27};

38 /**
39 * Bytes que hay que devolver por el cable por haber recibido este mensaje
40 * (vacío si no toca contestar nada):
41 * - el volcado que responde a una petición `0x10`/`0x0E`;
42 * - el acuse `0x23`/`0x24` de una escritura `0x40`/`0x4C` (guardada o no).
43 * El transporte MIDI lo manda tal cual; al importar un archivo se ignora.
44 */
45 std::vector<uint8_t> reply;
46};

56 /**
57 * Parses raw SysEx bytes (from .syx file or MIDI input).
58 *
59 * Peticiones reconocidas: `F0 7D 0A 10/0E F7` (ABDSynths) y
60 * `F0 42 3n 58 10/0E F7` (Korg) → `ProgramDumpRequest` / `AllDataDumpRequest`
61 * con `midiChannel` del canal pedido. La respuesta se construye con
62 * `buildProgramDumpResponse` / `buildAllDataDumpResponse`.
63 *
64 * Escrituras (`0x40`/`0x4C`) de ambas familias: además de guardarlas, el
65 * resultado lleva en `reply` el acuse que hay que devolver — `0x23` Write
66 * Completed si se guardó, `0x24` Write Error si no. Los acuses **recibidos**
67 * (`0x23`/`0x24`) se reconocen (`WriteCompleted` / `WriteError`) y no se contestan.
68 */

86 /**
87 * Respuesta a una `AllDataDumpRequest` **de Korg** (`F0 42 3n 58 0E F7`): la memoria
88 * completa con la cabecera del MS2000 (`F0 42 3n 58 4C ... F7`). Dos caminos:
89 *
90 * 1. Si llegó memoria del equipo (algún All Data Dump `0x4C`), sale **esa** — bytes
91 * intactos, incluido lo que el motor no modela — con el **programa activo refrescado
92 * desde el motor** para que el volcado refleje lo que se está oyendo.
93 * 2. Si nunca llegó, el plugin hace de equipo con **su propia memoria**: convierte sus
94 * 128 presets nativos a programas reales de 254 B (`MS2000HardwareProgram::
95 * fromNativeProgram`, conversión aproximada y declarada como tal — lo que el motor
96 * no modela sale del INIT Program del equipo). Ver §6.4 de
97 * `DOCS/ABDSynths_SysEx_Spec.md`; falta verificarlo contra hardware real.
98 */
99 std::vector<uint8_t> buildHardwareBankDumpResponse(int channel, const juce::AudioProcessorValueTreeState &apvts);

175 // - `MS2000ProgramData` (384 B, v2): el preset **propio** del plugin, el sistema
